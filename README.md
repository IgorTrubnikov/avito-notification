# Авито → Telegram на VPS (прототип 0.1)

Для Ubuntu 24.04, одного аккаунта Авито и VPS с 1 CPU / 2 ГБ RAM.
3x-ui/Xray не меняет. Нужен исходящий HTTPS к www.avito.ru и api.telegram.org.

**Текущий этап: уведомления при росте числа непрочитанных чатов**, как в исходном
расширении. Новое сообщение в уже непрочитанном чате может быть пропущено,
одновременное прочтение другого чата может скрыть рост. Это ещё не уведомления
о каждом сообщении. Для следующего этапа нужно проверить протокол отдельных
сообщений на реальной сессии. Доступ Авито с IP VPS, капча, срок сессии и
работа метода вне расширения требуют проверки на сервере.

Браузер запускается на VPS. Личный компьютер нужен только для входа или
повторной авторизации. Используются обычная сессия и метод из расширения;
обхода капчи или антибот-защиты нет.

## 1. Подготовка

Если Docker уже установлен для 3x-ui, не переустанавливайте его. Проверьте:

```bash
docker --version
docker compose version
free -h
df -h /
```

Если Docker отсутствует, установите Docker Engine и Compose plugin по официальной
инструкции https://docs.docker.com/engine/install/ubuntu/ (Ubuntu 24.04 поддерживается).
Команды ниже выполняются пользователем с правами Docker, при необходимости через sudo.
Образ содержит Chromium и рабочий стол; для сборки нужно несколько ГБ свободного
диска. Сборка на одном ядре может занять несколько минут.

Загрузите папку проекта в `~/avito-notification` на VPS. Откройте эту папку:

```bash
cd ~/avito-notification
cp -n .env.example .env
chmod 600 .env
nano .env
docker compose build
```

В `.env` укажите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Токен создаётся через
@BotFather. Напишите своему боту `/start`. ID личного чата можно узнать у
@userinfobot; указывайте именно ID своего чата. Секреты вводите только на VPS,
не присылайте в чат, не добавляйте в Git. Если токен когда-либо публиковали,
замените его через BotFather. Интервал `POLL_SECONDS` — от 30 до 3600 секунд.

Проверка Telegram (отправит одно тестовое сообщение):

```bash
docker compose run --rm --no-deps bot telegram-test
```

## 2. Вход в Авито

Мониторинг и вход используют один профиль. Они должны работать по очереди;
дополнительная файловая блокировка не позволит запустить их одновременно.

На VPS:

```bash
docker compose --profile monitor stop bot
docker compose --profile login up -d login
docker compose logs --tail=40 login
```

На **своём компьютере**, в отдельном терминале, откройте SSH-туннель:

```bash
ssh -N -L 6080:127.0.0.1:6080 USER@VPS_IP
```

В локальном браузере откройте `http://127.0.0.1:6080/vnc.html`, нажмите Connect.
В окне Chromium войдите в Авито, пройдите SMS/капчу, убедитесь, что мессенджер
открывается. Не открывайте конкретные переписки без необходимости, чтобы случайно
не пометить их прочитанными. Затем на VPS:

```bash
docker compose --profile login stop login
docker compose --profile monitor up -d bot
docker compose logs -f --tail=50 bot
```

После этого туннель можно закрыть. Порт 6080 привязан только к loopback VPS;
не открывайте его наружу в firewall. У удалённого рабочего стола нет собственного
пароля — доступ разрешён только через SSH и локальным пользователям VPS.

## 3. Приёмочная проверка на VPS

1. Дождитесь `Avito check OK` в логах. Ошибка HTTP/не-JSON не подтверждает работу.
2. Прочитайте старые непрочитанные чаты и дождитесь следующей успешной проверки.
3. Попросите другой аккаунт отправить сообщение в прочитанный чат.
4. В течение примерно 30 секунд должно прийти уведомление в Telegram.
5. Перезапустите `docker compose --profile monitor restart bot`: старое уведомление
   не должно повториться, сессия должна сохраниться.
6. Проверьте `docker stats --no-stream` и работу VPN одновременно с ботом.

Первый успешный опрос только запоминает исходное значение; старые непрочитанные
чаты при первом запуске не рассылаются. Лимиты бота: 0.75 CPU и 1100 МБ RAM,
они ограничивают нагрузку, но не гарантируют отсутствие влияния на VPN.
При OOM (`docker inspect` контейнера, поле State.OOMKilled) нужно пересмотреть
ресурсы или вынести бота. Не увеличивайте лимит до всей памяти VPS.

## Эксплуатация

```bash
# Статус и нагрузка
docker compose --profile monitor ps
docker stats --no-stream
# Логи без токенов и содержимого переписок
docker compose logs --tail=100 bot
# Остановить
docker compose --profile monitor stop bot
# Запустить после остановки
docker compose --profile monitor up -d bot
```

При проблемах Авито интервалы растут до 5 минут. После более 5 минут ошибок
в очередь ставится предупреждение, после восстановления — сообщение о восстановлении.
Ошибки сети и изменения протокола не объявляются автоматически истёкшей сессией.
Если требуется вход, повторите раздел 2. При отсутствии связи с самим Telegram
предупреждение придёт только после её восстановления.

Очередь SQLite сохраняется до подтверждённой отправки. После перезапуска
неотправленные уведомления повторяются. Если Telegram принял сообщение, но ответ
потерялся, повтор возможен: строгой гарантии «ровно один раз» Bot API не даёт.
Сообщения, пришедшие и прочитанные между опросами, обнаружить по счётчику нельзя.

Профиль, cookies и БД находятся в Docker volume `avito-data`. Считайте volume
секретным: он даёт доступ к аккаунту. Не используйте `docker compose down -v`,
если хотите сохранить авторизацию и очередь. Процессы запускаются от пользователя
node; Chromium работает с стандартными настройками Playwright без sandbox внутри
контейнера, поэтому используйте этот браузер только для Авито. Не публикуйте VNC
или отладочные порты. Логи ограничены двумя файлами по 5 МБ на сервис.

## Разработка и подтверждённые локальные проверки

Node.js 24+, системный Chromium:

```bash
npm ci
npm test
```

Тесты проверяют SQLite (перезапуск, очередь, отсутствие повторов при неизменном
счётчике), ошибки Telegram и реальный Chromium с подменёнными ответами Авито.
Это проверка интеграционного кода, **не успешный вход в настоящий аккаунт**.
Проверено при подготовке: 4 теста прошли на хосте и внутри Docker-образа;
экран noVNC отвечает HTTP 200, WebSocket подключается к удалённому дисплею.
Сборка в облачной среде использовала её доверенный CA через временный BuildKit
secret, без отключения TLS и без сохранения CA в поставляемом образе.
Вход в реальный аккаунт Авито, реальные сообщения Telegram и работа с IP вашего
VPS ещё не проверены. Для этого выполните разделы 1–3.
